# Cooperative seat routing and parity

`relay <session>:<seat> <text>` resolves the target adapter; `relay orcha <text>` uses the caller's declared orchestrator, and `relay status [message-id]` reads durable outcomes. Terminal ancestry binds interactive sources. Shared app-server calls never use inherited pane hints. Missing, ambiguous or stale source context refuses even for explicit destinations; cwd, active clients, payload project names and sender overrides never establish a seat.

Version 2 of `relay-route-policy.json` assigns lead or worker roles to named seats. CC, Codex, canonical Node wrappers, Agy and Gemini have equal rights for the same role. Native binaries, signatures, window names and model footers do not confer orchestration authority. Declared leads can communicate with other declared leads. For cross-session relationships and the `orcha` shortcut, project workers use `worker_orchestrator`; project leads use `orchestrator_of`. These mappings do not restrict explicitly named same-session sends. The initial worker destinations remain their local project lead, avoiding a direct jump to the shadow orchestrator. The operator's rp-schema mapping remains to review-protocol:claude, now bidirectionally. A claude window's presence does not demote a Codex lead. Same-session sends remain permitted for every bound seat, including config:terra ↔ config:codex, per the operator ruling.

Policy files must remain user-owned regular files without group/other write permissions. Queued records retain source pane, actor/root process starts and socket identity. Canonical queue/clear caller proof, source liveness and target generation remain checked on retries and before input. Unknown source apps cannot gain cross-session lead rights. Legacy unbound records fail closed. Hostile same-account edits or direct tmux access are outside this cooperative boundary; the final snapshot-to-keystroke race remains.

Sender parsing is uniformly strict. Busy, draft, copy and overlays defer without clearing human input. Agy and targeted Codex now share durable queue and archive behavior with CC/Codex defaults. One target scheduler owns pending retries; target-local recovery avoids sweeping unrelated inboxes. Known no-input states retry, unknown outcomes stop. Public queue outcomes are one line with a message ID and review path; exit meanings remain compatible.

`relay --operator <session>:<seat> <text>` is exclusively for an explicit human interrupt/replace instruction. It bypasses relationship permissions while retaining live source, exact target, draft/action and uncertainty protections. Ordinary agent messages never invoke it. `relay <session>:<seat> --clear-draft --expect <text>` supports the same explicitly expected clearing action across adapters. ASCII input must fit one line; multiline, attachments, selection and ambiguous styling refuse. The old arbitrary 16-character ceiling is removed; width and fresh matching still bound the action.

The shared delivery module derives labels from the verified route source, including durable queue source context during detached delivery, preserving `terra (config:terra) [<model> <effort>]:` instead of deriving a neutral label from the transport worker. Shared app-server callers require a verified thread binding. Labels remain informative, never permissions.

Run the route guard, worker allowance, queue-route, queue, sender-tier and clear-draft regressions for permission parity and retained safety. `relay-parity-transport-regression.py <output-directory>` uses real canonical guards on private fixture terminals to test source binding, Node/native parity and durable queue labels. Separate composer transport suites may copy tools and explicitly stub routing to isolate UI behavior; those runs do not prove routing authority. `relay-route-transport-regression.py` checks unrelated workers and unresolved callers produce no input or inbox mutation. Private fixtures named claude/codex are test executables, never actual headless model processes.

Run `relay-gate-deadline-regression.py <output-directory>` for slow mocked routing gates and bounded submission jobs. Allowed slow checks submit once; denial/timeouts send no input where known. An outer submission timeout remains unknown and never auto-replays. Live review-protocol↔rp-schema model checks are coordinated by the operator after installation.

`relay source` inspects the current proven source. Installed stable: for a shared Codex app-server, first obtain `CODEX_THREAD_ID` from that exact visible interactive pane, then use `relay bind-source --operator <uuid> <session>:<seat>`. This registration writes a private runtime binding outside routing policy. Each pane has one active thread; a replacement thread retires the previous binding, and pane/socket/process generation changes require explicit re-registration. Unknown daemon threads refuse before creating a record. Do not infer bindings from cwd, titles or inherited pane hints. Legacy version-1 Codex records lack this source proof and refuse; inspect them before an explicit fresh send, never auto-replay unknown outcomes.

Ordinary messages use `<window> (<session>:<window>) [<model> <effort>]: <text>` for all adapters. Oversized messages retain that label with a bounded summary and `-- full: <archive path>`. If the complete labelled pointer cannot fit, delivery refuses before input. `relay-native-argv-regression.py`, `relay-source-binding-regression.py` and `relay-archive-label-regression.py` cover argument boundaries, source binding invalidation and uniform archive rendering.

Operator interrupt/replace prose retains the same label across adapters. Explicit operator slash/bang commands remain CLI actions. Legacy `CC_MSG_EXACT=1` refuses before input because its unlabelled agent-message contract conflicts with the uniform-label operator ruling.

Window/model labels derive from the verified source seat and a unique styled live footer below its cursor. Model/effort is explicitly unverified when unavailable, hidden or ambiguous. The archive retains this same label. Window names identify seats; model names never confer permissions.
