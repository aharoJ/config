# Cooperative source routing

`relay-route-guard` resolves source pane ancestry first, or a live `TMUX_PANE` hint when ancestry has no pane. An unresolved source refuses even if the target is explicit. Proven local sources may send within their own session. Cross-session sends require a signed native Claude runtime and an exact source/destination rule in the adjacent operator-maintained `relay-route-policy.json`; destinations are restricted to `config:claude` and `review-protocol:claude`. Initial policy names config, review-protocol, cvmapp and vetmed-absence-expansion Claude orchestrators. Agents must not add their own allowances; no environment flag or alternate policy path grants one. The policy must be operator/user-owned and not writable by group or others; install it with mode600.

Queued records retain their enqueue source pane, actor/root process starts and server socket identity. Retry and final input checks revoke stale source identities or changed policy. Legacy records without a source fail closed for manual review. Labels and composer parsing tiers never grant routing authority. This is a cooperative routing guard: malicious same-account modifications, fabricated queue state and direct tmux access are outside scope. The final check-to-keystroke interval remains a snapshot race.

Run `python3 tmux/tests/relay-route-guard-regression.py` and `python3 tmux/tests/queue-route-regression.py` for source/policy revocation and queue/clear entry checks. Run `python3 tmux/tests/relay-route-transport-regression.py <output-directory>` for private public-queue worker refusals and direct unresolved transport refusals, verifying zero input and no rejected-message inbox mutation. The composer guard regression now copies tools into its private scratch directory with an explicit routing mock; it continues to test composer transport behavior independently. Real routing is exercised by the separate source and private transport suites.
